# Сводная таблица: минимум из `nalog target.docx` vs наш XML-генератор vs данные small sample в веб-форме

Цель: зафиксировать в одном месте:
1. минимально обязательные / базовые поля из `nalog target.docx`;
2. что уже добавлено в наш XML-генератор;
3. чем это покрыто в текущем small sample в веб-форме.

Источники:
- `nalog docs/nalog target.docx`
- `nalog docs/ON_AKTREZRABP_1_971_01_01_00_03.xsd`
- `variants/modern-light/data/sample-data.json`
- текущий production-full XML генератор

## 5) Вывод

### Уже хорошо покрыто
У нас уже покрыт production-базис для:
- реквизитов акта;
- сторон;
- договора;
- сметы/допсоглашения;
- табличной части КС-2;
- сумм разделов;
- строк работ;
- подписанта;
- удержаний (пока с агрегированным `СвОРасч`).

### Где ещё есть запас роста
Если идти дальше в richer production XML, логичнее всего следующими слоями добавлять:
1. `ПодписантПодр`: реально выгружать `СтатПодп`, `ТипПодпис`, `Должн`
2. `ИнфПолРазд` и/или `ИнфПолФХЖ2` — только если действительно есть бизнес-смысл
3. `ОснСдачи`
4. при необходимости — более полный `ИдСмет`
5. потом уже переходить к тестам против реального Diadoc-валидатора

### Практический итог
Текущий small sample в веб-форме уже содержит достаточно данных, чтобы строить **production-full XML с полноценной табличной частью**.
Основной remaining gap сейчас не в табличной части, а в:
- richer подписи,
- richer служебных XML-блоках,
- и практической совместимости с Diadoc поверх XSD.
