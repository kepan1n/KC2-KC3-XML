## 2. Что именно разрешают `docx` и XSD по блокам КС-2

### Подтверждение из `docx`

В `nalog target.docx`:
- таблица **5.2** задаёт `НаимИСт` как обязательный множественный блок (`ОМ`);
- таблица **5.8** говорит, что внутри `НаимИСт` допустимы варианты:
  - `ВидРаб`
  - `Раздел`
  - `РасшифРес`
- таблица **5.9** прямо описывает `Раздел`, внутри которого есть множественные `СвВидРаб`.

### Подтверждение из XSD `1110335`

Проверка схемы показывает:
- `Документ/НаимИСт` → `maxOccurs="unbounded"`
- `НаимИСт/Раздел` → `maxOccurs="unbounded"`
- `НаимИСт/ВидРаб` → `maxOccurs="unbounded"`
- `НаимИСт/РасшифРес` → `maxOccurs="unbounded"`
- `Раздел/СвВидРаб` → `maxOccurs="unbounded"`

### Что это значит practically

Можно поддержать как минимум 3 сценария:

1. **Один `НаимИСт`, внутри много `Раздел`**
   - самый естественный вариант для нескольких листов КС-2, если мы хотим сложить их в единый документ.

2. **Несколько `НаимИСт`, по одному на каждый лист / блок КС-2**
   - это ещё ближе к исходному Excel;
   - XSD это допускает;
   - `docx` это не запрещает.

3. **Ресурсная детализация через `РасшифРес`**
   - пригодно для случаев, когда нужно передавать не только строку работы, но и детализацию материалов / ресурсов.

## 3. Важное ограничение формата: где множественность уже НЕ предусмотрена

Внутри одного P-файла остаются одиночными и потому не могут быть отдельными на каждый лист КС-2:

| Блок | Что это означает для бизнеса |
|---|---|
| `СвАктСдПр` | один номер/дата акта на файл |
| `СвПродПер/СвПер` | один текст операции и один общий период на файл |
| `ВсегоАктОтч` | один итог за отчетный период на файл |
| `ВсегоАктСНач` | один накопительный итог на файл |
| `НастрФормДок` | один набор настроек документа на файл |
| `СвОРасч` | один блок расчетов по договору на файл |

### Следствие

Если в Excel реально лежат **несколько самостоятельных актов КС-2** с разными:
- номерами,
- датами,
- периодами,
- основаниями сдачи,

то в одном подрядческом XML можно:
- либо **агрегировать** их в один документ,
- либо **разбивать на несколько P-файлов**.

Полностью сохранить несколько самостоятельных шапок КС-2 внутри одного `1110335` без компромисса нельзя.

### 4.4. Разделение ролей «застройщик» и «технический заказчик»

В Excel и в форме это **две отдельные бизнес-роли**:
- застройщик;
- технический заказчик.

Сейчас в P-файле на стороне заказчика используется по сути **одна роль `СвЗак`**, в которую попадает:
- либо техзаказчик,
- либо застройщик (как fallback).

| Информация | Сейчас | Что говорит формат |
|---|---|---|
| отдельный застройщик как отдельная сторона | не передаётся отдельно | в основном составе `1110335` отдельного второго блока стороны заказчика нет |
| отдельный ОКПО застройщика | теряется, если основным `СвЗак` выбран техзаказчик | прямого второго штатного места нет |
| отдельный техзаказчик одновременно с застройщиком | не передаётся как две раздельные стороны | нужно решать через `ДопПолеСтрИнф` или договорённость по маппингу |

### Вывод

Это не просто пробел генератора, а частично **ограничение логической модели**. Формат лучше ложится на модель:
- один подрядчик,
- один заказчик.

Если бизнес хочет хранить и застройщика, и техзаказчика раздельно, это надо делать либо:
- через дополнительные структурированные поля,
- либо через жёсткое правило, кто считается `СвЗак`, а кто уходит в доп. информацию.

### 4.8. Детализация удержаний и авансов

Текущий генератор передаёт расчеты слишком агрегированно.

Что есть в Excel / форме:
- несколько строк удержаний / требований;

- незакрытый остаток прошлого периода;

Что уходит сейчас:
- только агрегированный `УчетТребУдерж`;
- только один вид требования/удержания;

| Информация | Сейчас | Что говорит формат |
|---|---|---|

Здесь есть **реальное сжатие бизнес-модели самим форматом**. Полная Excel-детализация удержаний в `1110335` напрямую не помещается.

## 6. Ответ на главный вопрос: можно ли добавлять дополнительные блоки КС-2?

### Короткий ответ

**Да, можно.**

### Но важно различать два разных смысла

#### А. Дополнительные табличные блоки КС-2

Это:
- новые разделы;
- новые строки работ;
- новые отдельные блоки `НаимИСт`;
- ресурсная детализация `РасшифРес`.

**Ответ:**
- XSD: **да**
- `docx`: **да**
- текущий генератор: **реализовано только частично**

#### Б. Дополнительные самостоятельные акты КС-2 со своими шапками

Это:
- свой номер документа;
- своя дата;
- свой период;
- своё основание;
- свой комплект итогов.

**Ответ:**
- XSD: **нет, не как отдельные независимые «шапки» внутри одного файла**
- `docx`: логическая модель также **не описывает несколько `СвАктСдПр` в одном P-файле**

### Практический вывод

Если нам нужно сохранить несколько КС-2 из Excel, есть два пути:

1. **Один P-файл, но с агрегированной шапкой**
   - несколько блоков `НаимИСт` / `Раздел` / `СвВидРаб`
   - один общий номер/дата/период документа

2. **Несколько P-файлов**
   - если важно не потерять самостоятельность каждого акта КС-2

## 7. Что стоит делать следующим этапом

### Приоритет 1 — без конфликта с форматом

1. Добавить в P:
   - `НачПерВДок`
   - `ОконПерВДок`
   - живой `СодОпер` из формы
   - множественные `ОснСдачи`

2. Разрешить **несколько `НаимИСт`**:
   - по одному блоку на каждый лист КС-2,
   - либо по одному блоку на логический комплект строк.

3. Добавить ветку:
   - `ИзмСмет`
   - **или** `ИзмСметНет`

4. Доделать доверенность подписанта подрядчика в P:
   - `СвДовер`
   - `СвДоверБум`

### Приоритет 2 — richer business profile

5. Добавить `РасшифРес` для материалов / ресурсной детализации.
6. Продумать правило, как хранить одновременно:
   - застройщика,
   - техзаказчика,
   - заказчика
   если формат даёт только один штатный `СвЗак`.

### Приоритет 3 — архитектурное решение

7. Определить правило для multi-KS2:
   - **или** один агрегированный P-файл,
   - **или** один P-файл на каждый самостоятельный КС-2.

## 8. Итоговая позиция

- **Дополнительные блоки КС-2 форматом предусмотрены** — и XSD, и `docx` это подтверждают.
- **Дополнительные самостоятельные шапки КС-2 внутри одного P-файла форматом не предусмотрены**.
- Главные реальные пробелы на сегодня:
  1. период документа (`НачПерВДок` / `ОконПерВДок`);
  2. множественные `ОснСдачи`;
  3. несколько `НаимИСт`;
  4. ресурсная детализация `РасшифРес`;
  5. корректная модель ролей застройщик / техзаказчик / заказчик;
  6. доверенность подписанта подрядчика в P;
  7. более честное решение для нескольких самостоятельных КС-2.
