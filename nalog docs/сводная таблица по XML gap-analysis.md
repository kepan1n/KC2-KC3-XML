## Короткий вывод

Сейчас наш XML уже проходит локальную XSD-валидацию, но по сравнению с `sample_1110335.xml` у него остаются 4 типа расхождений:

1. **Служебные/технические поля** — нужно ближе к sample-профилю.
2. **Агрегация бизнес-данных** — сейчас выгружаем слишком много строк `ВидРаб`, а sample-профиль агрегированнее.
3. **Постоянные XML-настройки** — у нас они берутся из UI, но для pass-профиля Диадока безопаснее дефолтить к значениям sample.
4. **Недостающие реквизиты первички** — часть полей отсутствует в Excel и должна жить в `Дополнительных полях для XML`.

## Что нельзя терять как бизнес-данные

| Данные | Почему критично |
|---|---|
| реальные `ВидРаб` / позиции КС-2 | это содержание акта |
| реальные `Раздел` и суммы по разделам | это бизнес-структура документа |
| реальные удержания и зачет аванса (`31`, `32`) | это финансовый смысл расчётов |
| реальные суммы `ВсегоАктОтч` | влияют на расчёты, НДС и сверку |
| реальные реквизиты договора / сторон | критично для юридического содержания |

## Практический план доработки

1. Ввести **режим безопасного Diadoc-профиля**:
   - дефолтить `ВерсПрог`, `НастрФормДок`, fallback-поля к pass-friendly значениям;
   - но не затирать реальные бизнес-данные, если пользователь их ввёл.

2. Добавить **валидацию полноты XML-реквизитов** до экспорта:
   - ИНН;
   - ФИО подписанта;
   - составитель файла;
   - допсоглашение / версия сметы;
   - адресные реквизиты.

3. Сделать **фильтрацию пустых разделов/строк**:
   - не выгружать `Раздел` со `СтБезНДСРаздОтч=0`, если он пустой;
   - не выгружать `СвВидРаб` с нулевой суммой без необходимости.

4. Ввести **режим агрегированного XML-представления**:
   - обычный режим: выгружаем полную бизнес-структуру;
   - safe-pass режим: укрупняем структуру ближе к `sample_1110335.xml`, если это нужно для валидации Диадока.

5. После этого — тестировать уже на валидаторе Диадока и фиксировать реальные расхождения отдельно.
