# Карта полей формы -> XML узлы (P + Z)

Цель: зафиксировать **текущее фактическое** соответствие полей web-формы и XML-выгрузки после перехода на canonical model:
- `documentContext`
- `xmlP.constants`
- `xmlP.manual`
- `xmlZ.manual`
- `xmlExtras`

Документ отражает текущее состояние генераторов `1110335` (P) и `1110336` (Z) для **non-gov** сценария.

## Статусы

- **уже передаётся** — поле реально уходит в XML сейчас
- **частично / через ИнфПол** — значение сохраняется в XML, но не в основном контрактном узле, а в `ИнфПол...` / fallback-структуре
- **не передаётся** — поле остаётся UI-only
- **нужно внедрить** — доменно нужно, но в коде ещё нет

## 11. Важное замечание про Z-время и локальную XSD

Есть зафиксированный конфликт источников:

- `nalog target.docx` требует время в формате **`ЧЧ:ММ:СС`** для `ВрИнфЗак` и `ВремяФайлИнфПодр`
- локальный файл `nalog docs/ON_AKTREZRABZ.xsd` всё ещё ожидает старый шаблон **`ЧЧ.ММ.СС`**

Поэтому текущее решение такое:
- production generator пишет **`ЧЧ:ММ:СС`**
- локальные regression / preview validation для Z нормализуют эти два атрибута под старую XSD только на этапе проверки

То есть источником истины для экспорта здесь считается **DOCX**, а не устаревшая локальная Z-XSD.
